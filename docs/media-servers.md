# Media Servers (Plex, Jellyfin, and Dupelix)

**Settings > Media servers** holds SRTL's connections to Plex, Jellyfin, and Dupelix. Each server is added once and shared by every feature that reads media servers: [watch sync](watch-sync.md) (Plex and Jellyfin) and [Now Playing](now-playing.md) (all three) today, and invitations as they arrive. Other integrations stay in **Settings > Integrations**.

Each server shows its type, URL, status (connected, error, not checked, or not signed in), the server version, and, for Plex, the plex.tv account it is signed in as. Both the SRTL API and the worker need network access to the servers.

## Add a server

**Add server** opens a menu of the server types; pick one to open its form. The button is unavailable while a form is open or when SRTL already has the most servers it supports.

- **Plex**: select **Add server > Plex**, enter a name and the server URL (for example `http://192.168.1.10:32400`), and select **Add and sign in with Plex**. SRTL adds the server and opens a plex.tv window straight away; sign in as the account that **owns** the server and approve "SRTL Manager". Two-factor authentication works as usual. SRTL notices the approval within a few seconds, stores the account token, and tests the connection. If the window was blocked, use the "open it here" link on the server's card; a sign-in that is not approved in about 15 minutes expires, and **Sign in with Plex** on the card starts a new one.
- **Jellyfin**: create an API key in Jellyfin under **Dashboard > API Keys**, then select **Add server > Jellyfin** with a name, the URL (for example `http://192.168.1.10:8096`), and the key.
- **Dupelix**: as a Dupelix administrator, create an API key under **Admin > Integrations**. Dupelix's key form lists permissions by name; the ids in brackets are only for support. The key needs the Dupelix permission **See who is watching** (`activity.read`), which lets SRTL list the streams playing now; streams carry their own artwork. Four more are optional: **Stop playback streams** (`activity.stop`) for the Stop button, **See playback client IP addresses** (`activity.network`) for client addresses, their location, and the LAN or WAN label, **Let API keys created by this role include guests' streams** (`activity.guests`) for guest profiles' streams (and stopping them), and **Browse the library** (`library.read`), which lets SRTL look up a title's artwork when a stream carries none. A key that never expires suits SRTL; keys survive their creator signing out or changing their password. A key becomes LAN only once another machine sends it to Dupelix over plain HTTP, and Dupelix then refuses it on its HTTPS address. Keys used on Dupelix's own address or on its integration network are not marked, so a key SRTL sends to a local integration route keeps working everywhere. If SRTL reaches Dupelix over plain HTTP from another machine, use a separate key for the HTTPS address. Then select **Add server > Dupelix** with a name, the server's address without `/api/v1`, and the key, which starts with `msk_`. The address can be the public HTTPS one the Dupelix apps use, or a local integration route Dupelix offers, such as its name on a shared Docker network or the host's LAN address with the integration port. SRTL sends the key on every request, including the version check, only in a single `Authorization` header, never in a URL, and never adds forwarding headers. See [Dupelix](#dupelix) below for what SRTL does with it.

If you cannot use the Plex sign-in, open **Or enter a token manually** in the add form (or in **Edit**) and paste your Plex account token; the button then reads **Add Plex server** and no plex.tv window opens. To find your token, open any item in Plex Web, choose **Get Info > View XML**, and copy the `X-Plex-Token` value from the address bar. Use your own account's token, never the `PlexOnlineToken` from the server's `Preferences.xml`. SRTL always identifies itself to Plex and Jellyfin as its own client ("SRTL Manager") with a stable client identifier.

**Sign in with Plex again** on a connected server's card reconnects it through plex.tv, for example after a Plex password change or when the connection stops working.

## Test, edit, and remove

- **Test connection** reaches the server with its token or key, records the version and status, and, for Plex, the machine identifier and owner account. For Dupelix it reads the server's version and API revision and asks Dupelix what the key may do. A local integration route answers 404 to anything it does not accept, so a 404 there reads "This address is not a Dupelix integration route", while an invalid or revoked key reads "Dupelix rejected the API key". The test also fails, with one short message in the server's status, when the key has expired, when it lacks a required permission (named the way Dupelix's key form names it), or when it is LAN only and the address is HTTPS, because every request would be refused. A Dupelix server's card shows the same details as a Plex or Jellyfin server's; SRTL never shows or keeps the key's name, any part of the key, its permissions or its expiry. Optional permissions the key lacks only hide the features they enable, such as Stop. A Dupelix server too old to describe its keys is checked with one page of streams instead. Features that use the server record their own failures on it too, so the status reflects the last request any of them made.
- **Edit** changes the name, URL, token or key, and path prefix mappings. Saved tokens and keys are never shown again; leave the field empty to keep the saved one. Changing a Jellyfin or Dupelix URL requires entering the API key again, so a saved key is never sent to an address you have not confirmed. Changing a Plex URL signs the server out for the same reason: its token and its users' tokens are cleared, so use **Sign in with Plex** again (then watch sync finds the users again), or paste a token with the change. Tokens and keys are stored encrypted with `SRTL_SECRET_KEY`.
- **Remove** forgets the connection and the per-server records SRTL kept for it (such as discovered users and the item index). Nothing changes on the server. A server that watch sync pairs still use cannot be removed; the message names the pairs to remove first.

## Path prefix mappings

Features match media by SRTL's symlink path. When a server mounts the library at the same place as SRTL (for example `/mnt/plex` everywhere), nothing is needed. Otherwise, map the server's prefix to SRTL's under **Edit > Path prefix mappings**; for example, a Plex container that sees `/data/media/...` while SRTL's symlink folder is `/mnt/plex` maps `/data/media` to `/mnt/plex`. The longest matching prefix wins, and prefixes only match whole folder names.

## Dupelix

Dupelix servers feed [Now Playing](now-playing.md). While someone has Now Playing open, SRTL follows Dupelix's activity stream (`/api/v1/activity/stream`), which pushes each change as it happens, so the server line reads **Live** like Plex and Jellyfin. It also reads the session list (`/api/v1/activity/sessions`) every 30 seconds as a safety net, and every 5 seconds while the stream is down or on a Dupelix older than API revision 152, which has no stream; the line then reads **Polling**. SRTL opens one stream per Dupelix server and closes it before opening another. Dupelix allows two streams per key, and from API revision 153 a third closes the key's oldest stream, so share SRTL's key with at most one other app that follows the stream, or better, give SRTL a key of its own. Guest profiles are listed when the key has **Let API keys created by this role include guests' streams** (`activity.guests`). SRTL reads the key's permissions again every ten minutes, so a permission added in Dupelix takes effect without a new test. Dupelix limits how many requests each key makes per minute (120 by default); opening the stream counts as one, a 5-second poll uses 12, artwork is cached by its signed link, and when Dupelix answers "too many requests" SRTL waits as long as it asks while the cards keep the last streams. Watch sync does not use Dupelix servers yet: they do not appear in it, and discovering users on one is refused.

Some details are not available from Dupelix yet, and the cards leave them out rather than guess. See [Now Playing](now-playing.md#dupelix) for the list. As Dupelix adds them, SRTL picks them up without a change in settings.

## Security

Plex tokens and Jellyfin and Dupelix API keys are stored only in SRTL's database. The browser never receives them; the API only reports whether one is saved. Up to 10 media servers can be connected.

Upgrading to a version with database migrations 39 and 40 lets media servers be Dupelix servers and keeps what Dupelix reports about each key. Existing Plex and Jellyfin servers are unchanged.

## Upgrading

Upgrading to a version with database migration 24 moves the servers that watch sync already had into Settings > Media servers. Each keeps its id, token or key, path mappings, and last status, so pairs, snapshots, and activity carry on without signing in again.
